# IP建档问题库与内容画像实施计划

> **供自动化执行者：** 必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans`，按任务逐项实施；所有步骤使用复选框跟踪，任何任务都不得跳过红灯测试、绿灯测试和提交检查点。

**目标：** 将现有“IP名称 + 自由介绍”建档升级为行业问题库驱动的可恢复建档流程，从每个行业至少30道受控问题中确定性选择8至10道，一次生成可追溯内容画像，并直接进入首篇口播稿创作。

**架构：** 问题库作为版本化代码资产随系统基线发布，确定性选择器只根据画像覆盖、结构化信号和优先级选择下一题。建档会话及答案保存在SQLite，画像服务只在用户确认答案摘要后调用一次模型；确认服务在单一事务中创建IP、首个账号、成员范围和当前上下文，同时保留旧画像字段兼容现有创作链路。

**技术栈：** Next.js 16 App Router、React 19、TypeScript 5.9、Zod 4、better-sqlite3、Vitest、Testing Library、Playwright。

**详细设计：** `docs/superpowers/specs/2026-08-18-IP建档问题库与内容画像详细设计.md`

## 全局约束

- 行业必须由用户主动选择，Agent不得推荐或猜测。
- 十个行业问题包均至少包含30道已启用问题。
- 每次建档选择8至10道问题，不随机抽题，不在问答阶段调用模型。
- 每道问题必须映射至少一个画像字段和一个选题信号。
- 画像生成默认一次模型调用，结构修复最多增加一次调用。
- 画像事实和长期选题方向必须带原始问题编号。
- 存量IP无需数据迁移即可继续生成选题和口播稿。
- 问题库版本随建档会话冻结，部署新版本不得改变进行中会话。
- 客户端不得自行读取完整问题库后决定下一题；下一题必须由服务端返回。
- 所有读写必须使用当前租户和当前用户范围校验。
- UI沿用现有纸张、墨色、朱红强调和单焦点任务语言，不引入侧边栏、卡片仪表盘、渐变、玻璃效果或胶囊导航。
- 当前工作区已有未提交代码改动；每次编辑前先检查目标文件差异，只提交本任务实际修改的文件。
- 在编写Next.js Route Handler或页面代码前，读取 `prototype/node_modules/next/dist/docs/` 中对应App Router文档。

const scoreQuestion = (question: PortraitQuestion, coverage: PortraitCoverage, signals: Set<string>) => {
  const triggerSignals = question.trigger.kind === "answer_signal" ? question.trigger.signals : []
  return (coverage.missingDimensions.has(question.dimension) ? 10_000 : 0)
    + question.priority * 10
    + triggerSignals.filter(signal => signals.has(signal)).length * 100
}

const stableOrder = (left: PortraitQuestion, right: PortraitQuestion) =>
  scoreQuestion(right, coverage, signals) - scoreQuestion(left, coverage, signals)
  || left.id.localeCompare(right.id)
