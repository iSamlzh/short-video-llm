# 团长内容增长工作台审计整改与 UI 改版实施计划

> **供 Agent 执行：** 实施时必须使用 `superpowers:subagent-driven-development`（推荐）或 `superpowers:executing-plans` 逐任务推进；所有步骤使用复选框跟踪。代码实施前必须先完成 Task 1 的 UI 方案评审，并取得用户明确确认。

**目标：** 修复工作台当前存在的账号状态、上下文切换、内容决策可信度、稿件状态、复盘颗粒度和可访问性问题，把“能生成稿件的原型”升级为可供团长及其运营人员长期使用的 AI-native 内容工作台。行业专属质量门禁不进入本轮实施。

**架构：** 保留现有 Next.js 16、React 19、SQLite、确定性服务层和模型适配器，不引入传统 SaaS 后台框架，也不在首版新增消息队列或多机基础设施。改造按“运行环境隔离 → 工作上下文 → 内容决策合同 → 结构化口播稿 → 发布复盘 → UI 与可访问性”分层实施，前端只展示服务端已经确认的数据事实，不自行推测账号状态或模型依据。

**技术栈：** Next.js 16、React 19、TypeScript 5.9、Zod、SQLite、Vitest、Testing Library、Playwright、原生 CSS、Phosphor Icons。

**设计依据：**

- `docs/superpowers/specs/2026-08-15-group-leader-content-growth-agent-design.md`
- `docs/superpowers/plans/2026-08-16-ai-native-daily-creation-ui-plan.md`
- 2026-08-18 操盘手全流程审计截图：`prototype/outputs/ip-operator-audit/`
- 本计划中的 P0/P1 问题清单与验收条件

## 全局约束

- [ ] 所有可见实施文档使用中文，专业类型名、接口名和测试命令可以保留英文。
- [ ] 第一版继续单机部署，不引入 Redis、队列、负载均衡、灾备或平台数据 API。
- [ ] 团长端默认进入当前 IP 的今日创作；只有首次建档或主动新增 IP 时进入建档。
- [ ] 平台内部爆款结构和原文证据不得下发团长端；团长端只展示经过脱敏的创作依据。
- [ ] “复制并去拍”只能复制已锁定版本；未锁定稿只能编辑、换题或确认定稿。
- [ ] 页面不得声称使用了不存在的数据，例如账号没有复盘数据时不得显示“已参考近期账号表现”。
- [ ] 本轮保留现有通用 QA，但界面只能表述为“内容检查”，不得表述为医疗、健康或其他行业的完整合规审查。
- [ ] 时长只根据 `spoken` 类型的口播文本计算，拍摄提示、字幕提示和合规备注不计入口播字数。
- [ ] 模型操作在 200ms 内显示已受理反馈，500ms 后显示阶段和已耗时；首版服务端仍使用 60 秒超时，不建设后台队列。
- [ ] 所有行为修改先写失败测试并观察 RED，再实现最小代码、验证 GREEN、最后提交。
- [ ] 不覆盖当前工作树中已有且与本计划无关的修改。

## UI Skill 选择

采用 GitHub 仓库 `ibelick/ui-skills`，主执行 Skill 为 `baseline-ui`，最终可访问性验收使用同仓库的 `fixing-accessibility`。

选择理由：

1. 面向真实 React/Next.js 工作界面，而不是只提供配色和审美提示；
2. 明确要求复用项目现有组件、补齐加载/空状态/错误状态、避免无效卡片和装饰性动效；
3. 覆盖图标按钮可访问名称、键盘焦点、表单错误、触控尺寸和颜色对比度；
4. MIT 许可，目录中提供标准 `SKILL.md`，可以通过 Codex Skill Installer 从 GitHub 安装；
5. 与现有 `design-taste-frontend` 分工清晰：Taste Skill 负责视觉个性与反模板化，`baseline-ui` 负责产品 UI 的工程约束和完整状态。

安装动作不在本计划编写阶段执行。用户确认后，通过 Skill Installer 从 `ibelick/ui-skills` 安装 `skills/baseline-ui` 和 `skills/fixing-accessibility`，重启 Codex 后再进入 UI 方案设计。

### Task 1：安装 UI Skill，并完成代码实施前的视觉方案审批

**产出：** 登录、首次建档、今日创作、生成等待、结构化编辑、发布复盘六个关键状态的桌面版和移动版视觉方案；此任务只产出设计，不修改产品代码。

**参考：** `ibelick/ui-skills/skills/baseline-ui`、`ibelick/ui-skills/skills/fixing-accessibility`、现有 `design-taste-frontend`。

- [ ] **步骤 1：安装并读取 UI Skill**

使用 Skill Installer 安装两个目录，确认 `SKILL.md` 可被 Codex 识别；安装后重新启动新的 Codex 会话。

- [ ] **步骤 2：确定视觉命题**

视觉方案必须围绕“内容导演台”而不是“运营后台”：稿件是主画面，决策依据是可展开的辅助层，当前任务始终只有一个主动作。不使用数据卡片宫格、装饰性大标题或与业务无关的渐变。

- [ ] **步骤 3：建立页面状态矩阵**

每个关键页面至少覆盖 `default`、`loading`、`empty`、`error`、`success`、`disabled`；今日创作额外覆盖 `draft`、`needs_qa`、`locked`、`published`。

- [ ] **步骤 4：输出同内容双视口方案**

桌面使用 1440×1000，移动端使用 390×844；两端必须使用同一套真实测试数据，避免用不同内容掩盖响应式问题。

- [ ] **步骤 5：用户逐页确认**

审批顺序固定为：全局导航与上下文 → 今日创作 → 结构化编辑 → 复盘 → 建档 → 登录。任何页面未确认，禁止进入 Task 2 的代码实施。

**验收：** 六个页面均有桌面与移动状态；所有按钮的最终名称、层级、状态和跳转已确定；用户明确回复“确认进入开发”。

## 本轮暂缓项

行业专属质量策略与硬门禁暂不实施，包括健康养生的医疗功效词、疾病治疗暗示、适用人群和证据来源规则。本轮只保留现有通用 QA，并把界面措辞降级为“内容检查”；不得展示“行业合规已通过”等结论。该能力后续单独立项，不阻塞以下任务。
