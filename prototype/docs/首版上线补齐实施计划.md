# 团长口播稿 Agent 首版上线补齐实施计划

> 制定日期：2026-08-26
> 适用范围：首版单机生产部署
> 目标：在不引入微服务、消息队列、平台数据 API 和数字人链路的前提下，把现有 PDCA 内容闭环补齐为可部署、可运营、可追溯的首版产品。

> 实施进度（2026-08-27）：第一批“模型任务可靠性”、第二批“真实团队管理与生产初始化”、第三批“IP 与内容账号管理”、第四批“历史内容中心”、第五批“生产部署与数据保护”已完成代码实施和验证；第六批文档与代码统一待实施。

## 一、范围确认

本轮纳入两类工作。

### 1. 上线前必须补齐

1. 模型任务可靠性、取消、总超时、幂等和成本控制；
2. 真实团队管理，移除“林姐 / 小周”固定演示逻辑；
3. 生产环境首个管理员、租户和团长账号初始化；
4. 可执行的单机部署、健康检查、备份和恢复能力；
5. 发布版本收口，完成构建、测试、部署验收、提交和远程推送。

### 2. 首版产品补齐

1. IP 与内容账号管理；
2. 历史内容中心；
3. 文档与代码统一。

### 3. 本轮不纳入

- 短信、邮件邀请和邀请链接接受流程；
- 用户自助注册、忘记密码和短信找回密码；
- 平台数据 API 自动回流；
- MiniMax 音频、HeyGen 数字人和最终成片；
- 产品侧自动内容质量门禁；
- PostgreSQL、Redis、任务队列、Worker 和多实例负载均衡；
- 蓝绿发布、自动回滚和跨机器灾备。

团队协作首版采用“团长直接创建下属账号、生成一次性临时密码、立即分配当前 IP / 内容账号权限”的方式。成员首次登录后必须修改临时密码；不依赖短信或邮件服务。

## 二、当前基线

现有系统已经具备以下主链路：

```text
首次 IP 建档
  → 生成选题池
  → 选择一个方向生成一篇口播稿
  → 按内容结构分段编辑
  → 人工确认定稿并下载 DOCX
  → 登记发布作品
  → 导入 CSV / XLSX 真实数据
  → 自动匹配与人工处理歧义
  → 生成复盘
  → 确认 IP 私有记忆
  → 使用记忆开始下一轮
```

当前单元测试基线为 70 个测试文件、346 项测试通过。当前工作区仍有未提交修改，因此本计划完成前不能把现有远程 `main` 视为可发布版本。

## 三、交付架构原则

1. 首版继续采用单个 Next.js Node 进程和单个 SQLite 文件。
2. 模型任务在当前进程内执行，但必须具备持久化任务记录、幂等保护、并发限制和明确状态。
3. 浏览器取消必须传递到服务端模型请求；取消后不得自动重试或继续生成第二次修复请求。
4. 平台爆款模板原文、内部名称和版本 ID 不进入团长端。
5. IP、账号、内容、发布、复盘和记忆全部按租户及数据范围鉴权。
6. 业务写入采用不可变版本或明确的状态迁移，不直接覆盖已经定稿、发布或形成复盘依据的数据。
7. 所有实施文档、运维说明和验收记录使用中文，代码专业术语不限制。

## 四、第一批：模型任务可靠性与成本控制（P0）

### 4.1 目标

解决模型请求时间过长、用户取消后服务端仍运行、重复点击可能产生重复费用、结构修复导致总耗时翻倍，以及缺少租户级成本边界的问题。

### 4.2 数据模型

新增 `model_tasks` 表：

```text
id
tenant_id
actor_user_id
run_id
operation
idempotency_key
status                 running | succeeded | failed | cancelled | timed_out
model
request_started_at
request_finished_at
prompt_tokens
completion_tokens
total_tokens
error_code
created_at
updated_at
```

约束：

- `tenant_id + idempotency_key` 唯一；
- 成功任务重复请求直接复用结果；
- 运行中任务重复请求返回当前任务状态，不再次调用模型；
- 失败、取消和超时任务必须显式由用户重试，系统不静默重复扣费。

### 4.3 服务端执行规则

1. 浏览器生成请求携带 `Idempotency-Key`。
2. Next.js 路由把 `request.signal` 逐层传入应用服务、RunService、StructuredLlmClient 和模型适配器。
3. 模型适配器合并客户端取消信号与服务端超时信号。
4. `LLM_TIMEOUT_SECONDS` 是整个业务操作的总预算，不是“首次生成”和“JSON 修复”各自独立的预算。
5. 首次响应无效时，仅在剩余时间和剩余 Token 预算允许的情况下执行一次结构修复。
6. 超时、取消、网络失败、限流和模型 5xx 使用不同稳定错误码。
7. 单机默认全局最多 10 个活动模型请求；单租户最多 2 个，参数可通过环境变量调整。
8. 超出并发限制时直接返回可重试状态，不在内存中无限排队。
9. 增加单租户日任务数和日 Token 上限；首版先使用环境变量配置，不建设计费后台。

### 4.4 可观测性

日志和任务表记录：请求 ID、任务 ID、租户、Run ID、模型、操作、耗时、Token 用量和稳定错误码。不得记录 API Key、完整建档回答、完整文稿和模型隐藏推理。

### 4.5 验收标准

- 点击取消后，模型连接在服务端终止，任务状态为 `cancelled`；
- 相同幂等键连续提交只产生一次模型调用；
- 结构修复不突破总超时；
- 超限租户收到明确提示，不影响其他租户；
- 管理日志可以核对一次任务的耗时和 Token 用量；
- 断网、429、5xx、超时和取消均有自动化测试。

### 4.6 实施状态（2026-08-26）

第一批已完成代码实现：

- 新增 Migration 015 与持久化 `model_tasks` 任务表；
- 创作选题、单篇口播稿和换选题/换表达请求已接入幂等键；
- 已实现全局 10、单租户 2 的默认并发边界，以及租户日任务数和日 Token 限额；
- 浏览器取消信号已贯通到服务端模型连接；
- 首次生成与一次 JSON 结构修复共享同一个总超时预算；
- 模型连接错误不再由服务端静默重试，避免上游已执行但响应丢失时重复扣费；
- 任务表仅保存状态、用量与 Run 引用，不保存完整画像回答或完整口播稿；

### 5.2 首次登录

下属账号使用临时密码登录后，只允许进入修改密码页；修改成功后撤销所有旧 Session，再进入工作台。

### 5.3 生产初始化命令

新增一次性命令：

```text
npm run init:production
```

输入通过环境变量或交互式安全输入提供，不把密码写入命令历史。命令负责：

1. 校验 `APP_ENV=production`；
2. 创建首个平台管理员；
3. 创建首个租户；
4. 创建租户 Owner；
5. 创建默认团队；
6. 写入审计记录；
7. 重复执行时拒绝覆盖现有正式账号。

### 5.4 验收标准

- 页面和接口中不存在固定“小周”查询；
- 团长可以创建两个不同下属账号并分配不同 IP / 账号范围；
- 下属不能查看未授权 IP、口播稿、发布数据和复盘；
- 停用后现有 Session 失效；
- 生产库可以不依赖 Demo Seed 完成首次初始化。

## 六、第三批：IP 与内容账号管理（P1）

### 6.1 页面入口

新增 `/app/settings/ip`，由工作台的 IP 切换器进入。页面采用“当前对象优先”，不做传统复杂后台表格。

### 6.2 IP 能力

- 查看当前画像摘要和画像版本；
- 修改 IP 名称；
- 重新校准画像：回到已保存回答，修改后生成新画像版本；
- 查看画像变化摘要；
- 归档未被使用的 IP；
- 已产生定稿、发布或复盘的 IP 只能归档，不能物理删除；
- 恢复已归档 IP；
- 切换默认 IP。

### 6.3 内容账号能力

- 为一个 IP 新增多个平台账号；
- 支持视频号、抖音、小红书、快手和其他平台；
- 修改账号显示名称；
- 设置默认内容账号；
- 停用和恢复账号；
- 已有发布数据的账号不能物理删除；
- 不同账号的发布、指标、复盘和记忆保持隔离。

### 6.4 验收标准

- 一个 IP 可以配置两个内容账号并独立创作、导入和复盘；
- 修改画像后旧 Run 仍引用旧画像版本，新 Run 使用新版本；
- 归档不会破坏历史文稿、发布和复盘；
- 越权成员不能管理未授权 IP 或账号。

- 文档不再声称首版一次生成三篇稿或自动 QA；
- 新成员可以仅依据 README 和运维文档完成本地启动、测试和单机部署。

### 9.3 实施结果（2026-08-27）

- 已删除无人引用的 `auto_draft`、`topic_draft`、三稿 Schema、Prompt 和 Service 分支；
- 正式链路及真实模型冒烟统一为“选题池一次 + 唯一方向单稿一次”；
- 自动 QA 只保留在生产环境固定 404 的原型兼容接口，正式定稿由用户人工确认；
- README、环境变量来源、接口、权限、数据谱系、发布验收和回退文档已统一；
- 定稿服务补齐 `content.lock` 服务端校验；
- 类型检查、373 条自动化测试、生产构建和 16 条浏览器回归通过；
- 真实模型诊断确认 Base URL、鉴权、Node 传输和极小生成正常；`terra` 正式选题连续超时，临时 `luna` 已完成选题与单篇稿，但选题耗时 108.6 秒并触发一次结构修复。模型路由和选题性能仍是上线前风险，未把“业务完成”误记为性能通过。

## 十、发布收口与质量标准（P0）

### 10.1 合入前

```text
npm run typecheck
npm test
npm run build

```

真实模型冒烟测试只执行最小的“生成选题 + 单篇口播稿”链路，并记录耗时和 Token，不输出密钥和完整正文。

### 10.2 人工验收

1. 使用生产初始化命令创建管理员和团长；
2. 团长创建一个 IP 和两个内容账号；
3. 创建下属账号并只授权其中一个账号；
4. 生成、编辑、定稿并下载口播稿；
5. 在历史内容中心找到并再次下载；
6. 登记发布，导入真实数据，生成复盘并确认记忆；
7. 使用记忆生成下一轮；
8. 验证下属无法查看未授权账号；
9. 执行备份并在隔离目录恢复；
10. 检查模型任务记录、Token、取消、超时和幂等状态。

### 10.3 Git 交付

- 每一批使用独立提交；
- 所有提交合入 `main` 前必须通过对应测试；
- 最终 `main` 与 `origin/main` 一致；
- 打首版候选标签；
- 记录数据库 Migration 版本、部署时间、回滚提交和备份位置。

## 十二、完成定义

以下条件全部满足，才可称为“首版上线补齐完成”：

- 团长端不存在固定演示身份和固定成员；
- 生产环境不依赖 Demo Seed；
- 模型请求可取消、可去重、受总超时和额度限制；
- 可以管理 IP、多个内容账号和真实下属账号；
- 可以检索、追溯和再次下载历史内容；
- PDCA 全链路通过 E2E；
- 单机部署、健康检查、备份和隔离恢复通过；
- 文档与代码一致；
- 所有改动已合入并推送远程 `main`。
