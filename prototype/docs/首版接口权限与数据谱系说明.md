# 团长内容增长 Agent 首版接口、权限与数据谱系说明

> 文档日期：2026-08-27
> 对应数据库 Migration：v19
> 适用范围：首版单机生产环境与同版本开发环境

## 一、正式产品边界

正式产品由两个安全域组成：

- 团长域：`/app/*` 页面和 `/api/app/*` 接口，只接受租户成员 Session；
- 平台运营域：`/platform/content-brain` 页面和 `/api/platform/content-brain/*` 接口，只接受平台运营身份。

`/api/prototype/*` 是开发调试兼容接口，不属于正式产品接口。它仅在非生产环境且显式设置 `ENABLE_PROTOTYPE_API=true` 时存在；生产环境固定返回 404。旧模拟发布、旧模型 QA 和旧复盘接口只能通过该隔离入口调用，不会进入团长正式创作链路。

正式创作的模型调用固定拆成两步：

1. 一次 `topics` 任务生成 3～5 个选题方向；
2. 用户采用一个方向后，一次 `scripts` 任务只生成一篇口播稿。

首版不调用自动质量门禁。用户编辑后人工确认事实、表达边界和可拍性，系统再锁定当前版本。

## 二、正式接口分组

所有业务接口默认使用同源 HttpOnly Session Cookie。除登录、存活和就绪检查外，未登录请求不能访问业务数据。错误响应使用稳定的 `errorCode`，不返回模型密钥、数据库路径、Session、完整上传文件或隐藏推理。

| 接口组 | 主要动作 | 主要能力或身份 |
| --- | --- | --- |
| `/api/auth/*` | 登录、退出、读取会话、首次修改密码 | 有效用户；首次临时密码登录后强制改密 |
| `/api/app/ip-onboarding/*` | 创建/恢复建档会话、逐题保存、复核、生成画像预览、确认建档 | 团长租户身份；创建者与租户范围校验 |
| `/api/app/context` | 读取和切换当前 IP/内容账号 | `ip.view`，且目标在成员授权范围内 |
| `/api/app/creation/*` | 读取今日结果、生成选题、单稿生成、换选题/讲法、保存、定稿、下载 | `content.create`、`content.edit`、`content.lock`；同时校验 IP/账号范围 |
| `/api/app/content/*` | 检索历史内容、查看详情和谱系 | `content.create`，且记录所属 IP/账号在授权范围内 |
| `/api/app/publications` | 登记发布、读取发布记录 | `publication.record`，且校验账号与定稿版本 |
| `/api/app/metrics/*` | 导入 CSV/XLSX、读取批次、确认或外部匹配 | `metrics.import`，且校验 IP/账号范围 |
| `/api/app/reviews/*` | 读取、生成、确认真实数据复盘 | `review.view`、`review.generate`、`review.confirm` |
| `/api/app/settings/ip/*` | 修改画像、归档/恢复 IP、管理内容账号和默认账号 | `ip.manage` |
| `/api/app/team/*` | 创建成员、修改授权、停用/恢复、重置临时密码 | `team.manage` |
| `/api/platform/content-brain/*` | 样本导入、拆解、人工复核、试生成、启用、停用和回滚结构 | 平台运营身份；启用、停用和回滚要求平台管理员 |
| `/api/health/live` | 进程存活 | 无业务数据 |
| `/api/health/ready` | 配置、数据库写入、Migration、磁盘和模型近期状态 | 无业务数据；响应已脱敏 |

创作正式接口的关键动作如下：

| 方法与路径 | 语义 | 模型调用 |
| --- | --- | --- |
| `GET /api/app/creation/current` | 读取当前 IP/账号当天已有结果 | 0 次 |
| `POST /api/app/creation/topics` | 创建 Run 并生成选题池 | 1 次 `topics` |
| `POST /api/app/creation/scripts` | 为传入的唯一选题生成一篇稿 | 1 次 `scripts` |
| `POST /api/app/creation/auto` | 旧版兼容入口，已通过响应头标记弃用；正式前端不得调用 | 兼容期最多 2 次，后续移除 |
| `POST /api/app/creation/next-round` | 依据已确认复盘记忆生成下一轮选题池 | 1 次 `topics`；单稿仍另调 `scripts` |
| `PUT /api/app/creation/runs/{runId}/draft` | 保存不可变文稿修订 | 0 次 |
| `POST /api/app/creation/runs/{runId}/finalize` | 人工确认并锁定当前修订 | 0 次 |
| `GET /api/app/creation/runs/{runId}/download` | 下载当前锁定版本 DOCX | 0 次 |

## 三、权限模型

### 3.1 三层校验

每次租户操作都同时校验：

1. 身份域：租户成员不能进入平台运营域，平台运营身份不能读取团长数据；
2. 能力：成员是否具备当前动作所需 Capability；
3. 数据范围：目标 IP 和内容账号是否同时在成员的持久授权范围内。

Owner 也通过同一套上下文执行，不依赖前端隐藏按钮。成员停用、密码重置或主动改密后，原有 Session 全部撤销。

### 3.2 默认角色

| 角色 | 创建时默认能力 | 默认用途 |
| --- | --- | --- |
| `owner` | 由生产初始化写入首版全部租户能力 | 团长负责人，管理成员、IP、账号和完整 PDCA |
| `operator` | `ip.view`、`content.create`、`content.edit`、`publication.record` | 选题、写稿、编辑、定稿前协作和发布登记 |
| `reviewer` | `ip.view`、`metrics.import`、`review.generate`、`review.view` | 导入真实数据并复盘 |
| `platform_operator` | 平台运营域操作 | 新增样本、拆解、修改和复核 |
| `platform_admin` | 平台运营域管理操作 | 在运营能力基础上启用、停用和回滚结构 |

Owner 可以在自己拥有的能力和 IP/账号范围内调整下属授权，不能授予自己没有的能力或数据范围，不能停用或重置自己。

### 3.3 Capability 说明

| Capability | 允许动作 |
| --- | --- |
| `ip.view` | 查看授权 IP/账号并切换当前工作上下文 |
| `content.create` | 生成选题、单篇口播稿和读取授权内容 |
| `content.edit` | 保存文稿新修订 |
| `content.lock` | 确认定稿 |
| `publication.record` | 登记真实发布身份 |
| `metrics.import` | 导入和匹配真实表现数据 |
| `review.generate` | 依据真实快照生成复盘 |
| `review.view` | 查看复盘 |
| `review.confirm` | 确认复盘并形成私有记忆 |
| `team.manage` | 创建、授权、停用成员和重置临时密码 |
| `ip.manage` | 修改、归档和恢复 IP/内容账号 |

## 四、数据谱系

### 4.1 身份与当前上下文

`users` → `sessions` → `memberships` → `membership_capabilities` / `membership_ip_scopes` / `membership_account_scopes` → `user_current_context`

- 用户是登录身份；租户是一个团长业务空间；成员关系把用户连接到租户；
- 当前 IP/账号只是用户工作偏好，不扩大权限；
- 当前对象失效时，只能在该成员已有授权范围内选择替代对象。

### 4.2 IP 建档与账号

`ip_onboarding_sessions` → `ip_profiles` → `ip_profile_versions` → `content_accounts`

- 建档会话绑定行业、题库版本和已确认回答，可中断恢复；
- 确认建档后产生正式 IP；每次修改画像新增不可变版本；
- 一个 IP 可以有多个平台内容账号，默认账号只影响当前选择；
- 归档不物理删除历史引用。

### 4.3 平台内容结构

`platform_content_samples` → `platform_content_sample_revisions` → `platform_content_analysis_versions` → `platform_structure_candidates` → `platform_structure_previews` → `platform_template_versions`

- 原始样本、授权说明、证据和运营备注只留在平台域；
- Agent 拆解和候选均需人工复核；
- 只有已启用的不可变结构版本可以被团长创作检索；
- `platform_template_activation_events` 记录启用、停用和回滚。

### 4.4 创作谱系

`runs` → `creation_run_context` → `topic_batches` → `topic_selections` → `script_batches` → `script_selections` → `locked_scripts`

- `creation_run_context` 锁定租户、操作者、IP、画像版本、内容账号、业务日期、结构版本、私有记忆版本和触发来源；
- 选题池与文稿修订按版本追加，不覆盖旧版本；
- 每次正式文稿任务只向 `script_batches` 写入一篇候选；
- `locked_scripts` 保存当前选中修订的内容哈希和不可变快照；
- 历史表中的 `quality_reports`、QA 状态名和模拟指标表为早期原型兼容结构，正式首版创作不写入自动 QA 报告，也不以其阻断锁稿。

### 4.5 发布、指标、复盘和记忆

`locked_scripts` → `publications` → `metric_import_batches` / `real_metric_snapshots` → `publication_match_versions` → `content_review_versions` / `review_evidence_links` → `tenant_memory_versions`

- 发布记录先绑定 Run、锁稿版本、IP 和内容账号；
- 指标导入保存批次摘要、脱敏行错误和不可变真实快照，不保存原上传文件；
- 匹配优先使用作品 ID、规范化链接，其次使用标题与发布时间，并允许人工确认；
- 复盘只能引用已匹配真实快照，证据链接可追溯；
- 用户确认后才形成租户/IP/账号私有记忆；私有记忆不会回写平台模板库；
- 下一轮 Run 在 `creation_run_context` 锁定实际使用的记忆版本和来源复盘。

### 4.6 模型任务与审计

`model_tasks` 记录业务操作、幂等键、状态、模型名、耗时、Token、错误码、取消状态和 `request_id`，可与 Nginx、API、模型日志串联，不记录 API Key 或完整正文。v19 起按 `scope_type + scope_id` 隔离计量：团长任务使用 `tenant` 作用域，平台爆款拆解使用独立 `platform` 作用域，二者不共用单作用域并发和日额度，但共同受全局并发上限保护。`audit_logs` 记录成员授权等关键管理动作。

所有正式真实模型入口统一经过 ModelTaskService：

| 业务入口 | 任务操作 | 作用域 | 幂等要求 |
| --- | --- | --- | --- |
| IP 画像预览 | `ip.portrait.preview` | 租户 | 必须传 `Idempotency-Key` |
| 选题池 | `creation.topics.*` | 租户 | 必须传 `Idempotency-Key` |
| 单篇口播稿 | `creation.script` | 租户 | 必须传 `Idempotency-Key` |
| 真实数据复盘 | `review.generate` | 租户 | 必须传 `Idempotency-Key` |
| 爆款样本拆解 | `content_brain.analysis` | 平台 | 必须传 `Idempotency-Key` |
| 结构候选生成 | `content_brain.structure_candidate` | 平台 | 必须传 `Idempotency-Key` |
| 结构试生成 | `content_brain.structure_preview` | 平台 | 必须传 `Idempotency-Key` |

统一治理包括：同作用域幂等去重、全局与作用域并发上限、每日任务数和 Token 额度、请求级超时/取消、模型用量累计、失败状态以及 `request_id → model_task_id → run_id` 追踪。非模型写操作不占用模型额度。

## 五、环境和兼容性约定

- 环境变量定义唯一来源是仓库根目录 `.env.example`；
- 生产安全组合由 `src/lib/runtime-environment-validation.ts` 强制校验；
- 功能开关解析以 `src/lib/runtime-features.ts` 为准；
- 最新数据库版本以 `src/lib/db/migrations.ts` 的 `LATEST_MIGRATION_VERSION` 为准；
- 旧表和旧状态名暂时保留是为了读取既有数据，不代表正式入口继续执行旧流程；
- `/api/app/creation/auto`、`/api/app/ip-profiles` 和 `/api/app/ip-profiles/preview` 仅为旧调用方提供一版迁移窗口，响应包含 `Deprecation`、`Warning` 和后继接口 `Link`；正式界面只使用 onboarding、topics 和 scripts；
- 不允许通过手工改库跳过 Migration 或直接覆盖历史版本。
