# 爆款拆解后台任务实施说明

## 一、目标

爆款样本保存后，接口立即返回 Agent 任务，不让浏览器同步等待模型完成。用户可以刷新、关闭或离开页面；任务由服务器后台继续执行，完成后进入人工复核，失败时保留可诊断状态和可操作的重试入口。

## 二、职责划分

- `platform_content_samples`：保存样本及业务工作流状态，例如待拆解、拆解中、待复核和拆解失败。
- `agent_jobs`：保存 Agent 编排状态，包括排队、阶段、心跳、重试次数、错误和结果引用。
- `model_tasks`：保存模型调用并发、额度、Token 用量和模型错误，不承担业务页面进度。
- Web 服务：鉴权、创建任务、查询任务状态、呈现轮询结果。
- 内容拆解 Worker：原子认领任务、调用模型、更新阶段、执行自动重试并保存结果引用。

## 三、任务状态

任务终态和运行态为：

```text
queued → running → succeeded
                 ↘ failed
                 ↘ timed_out
                 ↘ cancelled
```

页面展示的真实阶段为：

```text
queued
source_validation
structure_analysis
evidence_validation
persistence
review_ready
```

单次 LLM 调用无法提供准确完成百分比，因此页面不伪造百分比，只展示当前阶段、已运行时间和心跳状态。批量任务的“已完成数/总数”来自真实终态计数。

## 四、接口

### 创建拆解任务

```http
POST /api/platform/content-brain/samples/{sampleId}/analyze
Idempotency-Key: <客户端生成的唯一值>
Content-Type: application/json

{"batchId":"可选的 UUID"}
```

成功返回 `202 Accepted` 和完整任务状态。相同样本已经存在排队或运行任务时，返回原任务，不重复调用模型。

### 查询任务

```http
GET /api/platform/content-brain/tasks/{taskId}
GET /api/platform/content-brain/tasks?limit=100
```

仅平台运营身份可以读取，租户账号无法访问。

### 人工重试

```http
POST /api/platform/content-brain/tasks/{taskId}/retry
Idempotency-Key: <新的唯一值>
Content-Type: application/json

{}
```

只允许重试明确标记为可重试的失败或超时任务。重试创建子任务并保留 `parent_job_id`，不覆盖原失败记录。

## 五、重试与恢复

- 默认每条任务最多自动执行 2 次，即首次失败后自动重试 1 次。
- 自动重试采用短暂指数退避，当前为 2 秒起步，最大 15 秒。
- 模型超时、限流、模型结构校验失败、证据校验失败、模型并发限制和 Worker 中断属于可重试错误。
- Worker 每 5 秒更新心跳；默认 120 秒没有心跳的运行任务会在下次 Worker 启动或队列扫描时重新排队。
- 最终失败保存稳定错误码，页面提供中文原因和人工“重新拆解”操作。

## 六、单机部署

生产环境运行两个 systemd 服务：

```text
content-agent.service         Next.js Web 服务
content-agent-worker.service  爆款拆解 Worker
```

两者位于同一台服务器，使用同一个本地 SQLite 文件。数据库启用 WAL、`busy_timeout=5000`、`synchronous=NORMAL` 和外键校验；任务认领在数据库事务中完成，同一样本只允许一个排队或运行任务。

生产环境必须保持：

```text
CONTENT_ANALYSIS_INLINE_WORKER=false
CONTENT_ANALYSIS_WORKER_CONCURRENCY=2
AGENT_JOB_STALE_SECONDS=120
```

开发环境未显式关闭时允许 Web 进程内启动轻量 Worker，方便本地调试。正式环境由独立 systemd Worker 执行，Web 进程不后台消费任务。

## 七、日志与验收

Worker 正常日志写入 `/var/log/content-agent/worker-access.jsonl`，异常日志写入 `/var/log/content-agent/worker-error.jsonl`。正常日志保留 14 天，异常日志保留 90 天。

上线验收至少覆盖：

1. 创建任务接口在模型完成前返回 `202`；
2. 页面刷新后能恢复排队或运行状态；
3. 用户离开页面后任务继续完成；
4. 同一样本重复提交不会产生两个运行任务；
5. 批量任务显示真实完成数、处理中数量和等待数量；
6. 超时自动重试一次，最终失败可人工重试；
7. Worker 重启后可恢复失去心跳的任务；
8. 任务表不保存样本正文、Prompt 或完整拆解结果。
